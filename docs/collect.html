Send your DDR5 SPD dump to the spdr project

The spdr project decodes DDR5 memory modules. It can only get better by being tested against real modules, and the only way to get those is from people who own them. This page does the fiddly part: it reads your dump, removes the one piece of data that identifies your module, checks that the result is still a faithful image, and hands you a file you can send.

Nothing here leaves your computer. This page has no server and makes no network request. Your file is read by the browser, in this tab, and never sent anywhere until you send it to GitHub yourself.

  4. Open the upload page in your copy and drag the file you downloaded into it. Type a branch name like fixture/my-module in the box that asks for the branch, and make sure the folder is spdr/tests/fixtures.
  5. Commit it. GitHub then offers you a link to open a pull request. Say what the module is, and paste the provenance text in the description.

The maintainer will check the provenance and may reword the entry. That is expected: the facts come from the file, the wording is theirs.

How do I get a dump in the first place?

This is the hard part, and it is a hardware problem rather than a software one: the SPD lives on the SMBus of the memory module, and getting it out needs either a UEFI tool or administrator rights on Linux.

Linux. The kernel exposes the module's EEPROM as a file:

dd if=/sys/bus/i2c/drivers/ee1004/0-0050/eeprom of=dump.bin

The bus and device address differ from machine to machine; i2cdetect -l lists them. The ee1004 driver is the one that works for DDR5.

Windows. A UEFI tool such as RWEverything can write the SMBus to a file from a UEFI shell. Booting into the UEFI shell and running it there is usually the easiest route.

Either way. If you would rather not produce a binary file, hexdump -C dump.bin > dump.txt produces a text dump this page reads just as well.
